Resource management nodes give your workflows direct access to the files stored in your projects. Instead of manually passing data between steps outside the platform, you can load a dataset from project storage, pass it to a training or prediction node, and save the result back — all within a single workflow. This keeps your data pipeline self-contained, reproducible, and version-tracked.

## What you can do

<CardGroup cols={2}>
  <Card title="Load resources" icon="file-arrow-down">
    Read a dataset, model artefact, or configuration file stored in a project and pass it as input to any downstream node.
  </Card>
  <Card title="Save resources" icon="file-arrow-up">
    Write a node's output back to project storage as a new resource or a new version of an existing one, making results available to future workflows.
  </Card>
</CardGroup>

## Key types

The `TabularData` type from `uncertainty_engine_types` represents CSV-based datasets. When a resource management node loads a tabular file, it returns a `TabularData` object that you can pass directly to machine learning or other nodes. If you need to inspect the data locally, `TabularData` supports conversion to a pandas `DataFrame`:

```python
from uncertainty_engine_types import TabularData

# Convert a TabularData object to a pandas DataFrame for local inspection
df = tabular_data.to_dataframe()
```

<Note>
  pandas integration requires the `data` optional extra. Install it with `pip install "uncertainty-engine[data]"`.
</Note>

## Discovering resource management nodes

Use `client.list_nodes` to retrieve the current set of resource management node identifiers and `client.get_node_info` to inspect their input and output schemas before building your workflow.

```python
from uncertainty_engine import Client

client = Client()
client.authenticate()

# Discover all available resource management nodes
rm_nodes = client.list_nodes(category="ResourceManagement")
for node in rm_nodes:
    print(node["node_id"], node.get("description", ""))

# Inspect the schema for a specific node
# Replace "LoadResource" and "1.0.0" with values returned by list_nodes above
info = client.get_node_info("LoadResource", "1.0.0")
print(info.inputs)
print(info.outputs)
```

## Building a workflow with resource nodes

The pattern below shows how to construct a `Graph` that loads a dataset from project storage, passes it to a processing node, and saves the result back. Use `client.list_nodes(category="ResourceManagement")` to confirm the exact node identifiers for load and save operations in your environment.

```python
from uncertainty_engine import Client
from uncertainty_engine.graph import Graph

client = Client()
client.authenticate()

# Build the workflow graph
graph = Graph(prevent_node_overwrite=True)

# Add a load node — replace "LoadResource@1.0.0" with the actual node_id@version
graph.add_node(node="LoadResource@1.0.0", label="load")

# Add a processing node — replace with the actual node identifier
graph.add_node(node="ProcessData@1.0.0", label="process")

# Add a save node — replace "SaveResource@1.0.0" with the actual node_id@version
graph.add_node(node="SaveResource@1.0.0", label="save")

# Wire the dataset output of "load" into the processing node
graph.add_edge("load", "data", "process", "inputs")

# Wire the processing output into the save node
graph.add_edge("process", "outputs", "save", "data")

# Add any external inputs the graph requires
graph.add_input("project_id", "proj_id")
graph.add_input("resource_id", "dataset_id")
```

Once the graph is built, run it through the client:

```python
result = client.run_workflow(
    project_id="proj_id",
    workflow_id="workflow_id",
    inputs={},
    outputs=["save"]
)
print(result)
```

<Note>
  Node identifiers such as <code>LoadResource@1.0.0</code>, <code>ProcessData@1.0.0</code>, and <code>SaveResource@1.0.0</code> are illustrative placeholders. Use <code>client.list_nodes(category="ResourceManagement")</code> to retrieve the exact identifiers available in your environment, then call <code>client.get_node_info(node_id, version)</code> to confirm the required input and output fields before wiring edges.
</Note>

## Typical operations

<AccordionGroup>
  <Accordion title="Load a dataset from a project">
    Reference a stored dataset by its project and resource identifiers. Discover the exact load node name with `client.list_nodes(category="ResourceManagement")`, then add it to your graph:

    ```python
    # Replace "LoadResource@1.0.0" with the actual node_id@version
    graph.add_node(node="LoadResource@1.0.0", label="load_data")
    ```

    The node retrieves the latest version of the resource unless you specify a version explicitly via its input schema.
  </Accordion>
  <Accordion title="Save a node output as a new resource">
    Write a node's output back to project storage. Saving creates a new resource version, preserving previous versions for reproducibility.

    ```python
    # Replace "SaveResource@1.0.0" with the actual node_id@version
    graph.add_node(node="SaveResource@1.0.0", label="save_output")
    graph.add_edge("process", "mean", "save_output", "data")
    ```
  </Accordion>
</AccordionGroup>

<Tip>
  Chain load, process, and save nodes in a single workflow to create fully automated, end-to-end data pipelines. Every resource write is versioned, so you can trace exactly which inputs produced a given output.
</Tip>
