Nodes are the discrete, versioned computational units that power every workflow on the Uncertainty Engine. Each node accepts a defined set of inputs, performs a specific operation on the platform's infrastructure, and returns structured outputs. Because nodes are independently versioned, you can pin a particular version in production while continuing to experiment with newer releases in development.

## Node categories

The platform organises nodes into five categories. Each category groups nodes that share a common purpose, so you can quickly find the right building block for your workflow.

## Discover nodes programmatically

You can explore the full node library at any time using the `Client`. Use `list_nodes` to retrieve every available node, optionally filtered by category, and `get_node_info` to inspect the exact inputs and outputs a specific node version expects.

```python
from uncertainty_engine import Client

client = Client()
client.authenticate()

# List all nodes across every category
all_nodes = client.list_nodes()

# Filter by category
ml_nodes = client.list_nodes(category="MachineLearning")

# Get details for a specific node and version
info = client.get_node_info("Add", "0.2.0")
print(info.inputs)
print(info.outputs)

# List all available versions of a node
versions = client.get_node_versions("Add")
```

You can also search the library by passing a list of `NodeQuery` objects to `query_nodes`. The result is a dictionary keyed by `"node_id@version"`:

```python
from uncertainty_engine import Client
from uncertainty_engine_types import NodeQuery

client = Client()
client.authenticate()

results = client.query_nodes([NodeQuery("regression"), NodeQuery("predict")])
for key, info in results.items():
    print(key, info)
```

## Node versioning

Every node on the platform carries a semantic version number. When you call `get_node_info`, always specify the version you intend to use so that the inputs and outputs you inspect match what the node actually receives at runtime.

<Note>
  Pin node versions in production workflows. The platform may introduce new node versions that change input or output schemas. Unversioned references default to the latest release, which can cause unexpected behaviour after a platform update.
</Note>

Use `get_node_versions` to list every published version of a node and confirm which release is current:

```python
versions = client.get_node_versions("Add")
for v in versions:
    print(v)
```
