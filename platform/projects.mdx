A project is the primary organisational unit inside the Uncertainty Engine. Every workflow you build and every resource you upload lives inside a project, so your team always has a single, well-scoped place to collaborate. Projects also act as the namespace for API calls — whenever you run a workflow or interact with a resource you supply the project ID alongside the resource identifier.

## What a project contains

Each project holds:

- **Workflows** — saved node graphs that team members can run, version, and share.
- **Resources** — uploaded files such as datasets and model artefacts that workflows reference.
- **Members** — all users who belong to your organisation can access shared projects, so there is no extra permission step beyond having a valid account.

<Note>
  Project IDs appear in every workflow and resource API call. Copy the ID from
  the web UI project settings page, or retrieve it via the REST Resource API
  as shown below.
</Note>

## Managing projects

Projects are created and managed through the **Uncertainty Engine web UI** or via the **REST Resource API**. The Resource API exposes endpoints for listing, creating, and deleting projects, authenticated with the `X-Resource-Service-Token` header.

For example, to list all projects for your organisation:

```http
GET /api/projects
X-Resource-Service-Token: <your-token>
```

See the [Resource API reference](/api-reference/rest-resources) for the full list of project endpoints, including request and response schemas.

## Use project IDs in SDK calls

Once you have a project ID (from the web UI or the Resource API), pass it to SDK methods that operate within a project context:

```python
from uncertainty_engine import Client

client = Client()
client.authenticate()

# Run a workflow inside a project
result = client.run_workflow(
    project_id="your_project_id",
    workflow_id="your_workflow_id",
    inputs=[],
)
print(result.outputs)
```

<Tip>
  Copy your project ID from the project settings page in the web UI, or
  retrieve it from the `GET /api/projects` endpoint. You will need it whenever
  you run a workflow or reference a resource in an SDK call.
</Tip>

See [Workflows](/platform/workflows) and [Resources](/platform/resources) for full details on these operations.
