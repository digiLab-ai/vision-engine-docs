Nodes are the pre-built computation units that power every workflow in the Uncertainty Engine. Each node encapsulates a specific operation — from simple arithmetic to training a machine-learning model — and exposes named input and output ports. You connect nodes together in a graph to build a complete workflow. The Python SDK gives you several methods for discovering what nodes are available, inspecting their signatures, and checking which versions are published.

## List all available nodes

Call `client.list_nodes()` without arguments to retrieve every node registered on the platform. The method returns a list of dictionaries, each containing at minimum the node ID, display name, and category.

```python
from uncertainty_engine import Client

client = Client()
client.authenticate()

nodes = client.list_nodes()
for node in nodes:
    print(node["node_id"], node["name"])
```

## Filter by category

Pass a `category` string to narrow the results to a specific group of nodes.

```python
ml_nodes = client.list_nodes(category="machine_learning")
for node in ml_nodes:
    print(node["node_id"], node["name"])
```

<Note>
  Category names are lowercase and use underscores. Use the exact strings shown in the
  categories table below.
</Note>

## Inspect a node's inputs and outputs

Call `client.get_node_info()` with a node ID and version to fetch the full schema for that node, including the names and types of all its input and output ports.

```python
info = client.get_node_info("basic/Add", 1)
print(info)
```

The returned `NodeInfo` object describes each input handle (name, type, whether it is required) and each output handle, so you know exactly what values to supply when building a graph or overriding inputs at run time.

<Note>
  `client.get_node_info()` raises `KeyError` if the node ID or version is not
  found on the platform.
</Note>

## Check available versions

Use `client.get_node_versions()` to see every published version of a node.

```python
versions = client.get_node_versions("basic/Add")
for version in versions:
    print(version)
```

Always note the version before adding a node to a graph. Pinning a specific version ensures your workflow behaves consistently even after the platform publishes updates.

<Note>
  `client.get_node_versions()` raises an `HTTPError` (404) if the node ID is
  not found on the platform.
</Note>

## Search for nodes by query

`client.query_nodes()` accepts a list of `NodeQuery` objects and returns the matching `NodeInfo` records keyed by `"node_id@version"`.

```python
from uncertainty_engine import Client, NodeQuery

client = Client()
client.authenticate()

results = client.query_nodes([
    NodeQuery(node_id="basic/Add", version=1),
    NodeQuery(node_id="basic/Number", version=1),
])
for key, info in results.items():
    print(key, info)
```

## Node versioning

Every node on the platform is independently versioned. When you call `graph.add_node()` you specify a `version` argument alongside the node ID and label:

```python
from uncertainty_engine import Client
from uncertainty_engine.graph import Graph

graph = Graph(prevent_node_overwrite=True)
graph.add_node(node="basic/Add", label="my_adder", version=1)
```

<Tip>
  Run `client.get_node_versions("basic/Add")` during development to confirm the
  latest stable version, then hard-code that value in your graph definition.
  This protects your workflow from unexpected behaviour if a newer version
  changes the node's interface.
</Tip>
